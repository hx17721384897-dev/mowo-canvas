# 技术架构

## 当前架构

```text
浏览器
  ↓ localhost
Next.js
  ├── React Flow 画布
  ├── 项目与素材页面
  └── 本地数据接口
        ├── SQLite
        └── 数据根目录下的 storage/（本地素材）
```

## 技术选择

- 语言：TypeScript
- Web 框架：Next.js App Router
- 画布：`@xyflow/react`
- 样式：Tailwind CSS
- 数据库：SQLite
- ORM：Drizzle ORM
- 素材存储：由服务端读取与源代码分离的数据根目录。实际路径由 `src/features/assets/server/data-paths.ts` 解析，配置见[本地运行](09-local-deployment.md)。

## 架构边界

- React Flow 组件只负责交互与前端状态，不直接操作数据库。
- 页面通过服务层或 Route Handler 调用数据能力。
- 数据访问通过 Repository/Service 封装，避免绑定 SQLite 实现。
- 画布 JSON 不包含图片、视频的 Base64 内容，只保存 `assetId`。
- 本地数据目录不进入 Git。
- 当前不引入 Redis、消息队列、容器编排或独立微服务。
- 当前不接入数据库 MCP；AI 通过仓库内的类型、Repository、迁移和验证脚本参与数据库开发。

## 平台下载模块

```text
下载弹窗
  ↓ localhost Route Handler
下载任务模块（SQLite 状态 + 临时文件）
  ↓
平台适配器
  └── LINE：TypeScript 实现
  ↓
资产模块（去重、集合、项目引用）
```

平台适配器负责把平台链接变成经过验证的临时下载项。B 站首版采用 SQLite 任务记录、单一执行者与独立 Python/yt-dlp/FFmpeg 工作进程；Node 服务编排扫码、状态、媒体校验、文件式确认入库与独立预览缓存。已有 Job Object 与文件锁继续使用，关闭弹窗不终止任务，重启后显示中断并由用户重试。首版不增加多协调器租约、导入意图日志、删除隔离和在线备份屏障。普通 npm 启动入口已统一管理 Next 与视频执行者，当前设计见[视频下载 V01](design/video-download-v01.md)。

## 资产模块

资产能力采用一个对页面和画布都稳定的模块接口，内部集中处理导入、内容去重、项目引用、集合顺序和安全删除。调用方只使用资产 ID，不判断文件具体存放位置。

```text
资产页 / 画布 / 下载功能
          ↓
资产模块
  ├── 资产目录：身份、类型、来源、集合、项目引用
  ├── 文件存储：图片与视频原文件
  └── 预览缓存：缩略图与视频封面
          ↓
      SQLite + 本地素材目录
```

从历史画布添加资产时，资产模块只建立新的项目关联，不复制原文件。未来需要国内对象存储时，只替换文件存储实现；资产身份、项目关系和画布中的 `assetId` 保持不变。

## 画布处理链

可组合功能采用“处理模块 → 结果模块 → 下一个处理模块”的稳定接口。处理模块接收兼容端口输入，只暴露必要设置、执行命令、状态和输出端口；复杂处理、缓存、去重、派生关系和错误恢复留在模块实现内部。可持久保存、再次查看或继续连接的输出进入独立结果模块，不嵌入处理模块卡片。

```text
图片模块（动图，可多条连接）
          ↓
动图拆帧处理模块（开始、进度、错误摘要）
          ↓
序列帧组结果模块（多个有序图片集合的引用）
          ↓
图片拼接处理模块（读取序列帧组）
```

结果模块保存资产或集合 ID，不在 React Flow 节点数据中复制正式图片内容。把某个折叠序列帧组拖到画布时，才创建一个真实 React Flow 组及其子图片模块；重复拖入只增加画布实例，不复制物理帧文件。

逐帧查看与图片下载弹窗可以共用对话框外壳、棋盘格预览台、缩略图网格和基础翻页控件等无业务状态的视觉模块。LINE 下载任务轮询、临时文件选择与导入归档属于下载实现；帧索引、时序播放、组切换和放入画布属于逐帧查看实现，两者不共享业务状态模块。

## 未来替换点

```text
SQLite              → PostgreSQL
本地素材存储          → 国内对象存储
本地单用户           → 账户与项目成员
localhost           → 国内云服务器、域名、HTTPS
单进程               → 按真实负载拆分后台任务
```

替换通过存储接口和数据库迁移完成，画布组件不应感知具体存储位置。

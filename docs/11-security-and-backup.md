# 安全与备份

## 当前风险重点

本地阶段最重要的不是公网攻击，而是误删除、磁盘损坏、程序升级覆盖数据和导入异常文件。

## 数据保护

- 源代码与运行数据分离。
- 自动备份不得覆盖唯一一份旧备份。
- 备份至少包含 SQLite 数据库、素材目录和数据版本信息。
- 恢复流程必须经过实际验证。
- 导入 JSON 前验证结构、版本和大小。
- 文件上传验证扩展名、MIME、大小和保存路径。
- 所有文件路径必须限制在预期数据目录内，防止路径穿越。

## 建议的备份层级

视频首版当前提供范围说明与停机复制约定，尚未提供自动备份界面或在线备份。先导入要保留的待下载结果，停止视频处理并退出所有 MOWO 实例，再一起复制数据根目录中的 `database/`、`storage/` 和 `data-version.json`。数据库目录需整体复制，不能在写入中只拿主 db 文件。`temp/` 不作为正式素材备份；`cache/` 可重建。凭据加密绑定 Windows 用户，不随素材分享，换账户后重新扫码。

恢复后先核对数据版本与正式原片，再启动应用。缺少临时原片的待入库任务会明确提示重新下载；正式原片缺失保留资产关联并提示恢复备份。没有引入在线备份屏障或下载现场自动恢复。隔离停机复制与预览重建验收记录见[视频下载进度](design/video-download-progress.md)。

- 自动轮换备份：用于日常误操作恢复。
- 手动里程碑备份：用于大版本升级前恢复。
- 独立介质副本：防止电脑或磁盘整体损坏。

## 代码安全

- API key、数据库密码、访问令牌和其他秘密只进入未提交的服务端环境变量。
- 前端只能读取明确公开、使用 `NEXT_PUBLIC_` 前缀且不含秘密的环境变量。
- `.env.example` 只提供变量名和说明，不包含真实值。
- 用户数据访问遵循最小权限；SQLite 阶段由服务层强制边界，未来使用支持 RLS 的数据库时再增加数据库层策略。
- 依赖升级单独审查并运行构建测试。
- 不执行来源不明模板中的安装脚本。
- 上线前重新进行认证、授权、上传和接口安全审查。

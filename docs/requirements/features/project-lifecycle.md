# 项目生命周期需求

## 目标

让用户从首页创建项目，并在以后重新打开时恢复同一份画布、工作流和对话上下文。

## 产品关系

第一版采用“一项目一画布”：项目是保存边界，画布是编辑区域，工作流是画布上的节点与连线，对话是项目的关联记录。

## 已确认需求

### REQ-PROJECT-001 从首条消息创建

用户在首页发送第一条消息时，自动创建一个新项目，不要求先完成单独的创建表单。

验收：创建成功后得到稳定项目标识，并进入该项目的画布路由。

### REQ-PROJECT-006 直接创建空白画布

用户可以通过首页右上角“新建画布”按钮创建一个不带首条对话内容的空白项目，并直接进入画布。

验收：该入口不依赖对话内容，也不会错误复用已有项目。

### REQ-PROJECT-002 过渡到画布

创建成功后应有简洁的过渡动画，使首页对话入口与画布右侧对话面板在视觉上形成连续关系。

验收：动画不阻塞项目创建；动画未播放或被中断时仍能正常进入画布。

### REQ-PROJECT-003 恢复项目

从最近项目或历史项目进入时，恢复对应项目的节点、连线、视口和对话记录。

验收：重新打开后不会进入空白新画布，也不会加载其他项目的数据。

### REQ-PROJECT-004 本地优先

第一版项目只保存在本机，不依赖登录、云端服务或海外托管。

验收：断网状态下仍可创建、打开和编辑本地项目。

### REQ-PROJECT-005 基础项目管理

项目列表支持打开、重命名和删除本地项目。删除属于破坏性操作，必须提供明确确认或可恢复机制。

验收：重命名后所有项目入口同步显示新名称；删除不会误伤其他项目。

## 待确认

- 自动命名规则。
- 项目页是否需要搜索、复制、筛选和排序。
- 原型阶段采用临时内存数据还是提前接入本地持久化。

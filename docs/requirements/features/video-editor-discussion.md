# 视频编辑页与镜头观察：讨论记录

> 本页记录页面与源码观察；已确认的产品行为见[视频编辑 PRD](video-editor.md)，当前技术路线和实施步骤见[视频编辑页技术设计](../../design/video-editor-architecture.md)。

## 目标场景

较大视频从素材库进入专门编辑页。用户提出先完成基础播放、准确逐帧查看、按时间选择并截取片段、把片段导回画布；自动分镜与镜头边界修正优先放在第二版讨论。这里的“视频裁切”已确认指**截取时间片段**，不指裁掉画面边缘。原片始终不因片段选择或镜头划分而改变。

## 建议的页面结构

用户已认可这套完整页面布局：中央大播放器，下方可缩放时间线与逐帧按钮，左侧镜头/片段列表，右侧调整边界并选择导回画布。按此前确定的分期，首期左侧先显示手动挑出的片段、右侧调整片段起止帧；第二期接入自动检测的镜头列表和镜头切点校正。完整布局不等于所有面板能力都在首期交付。

```text
顶部：返回画布｜视频名称和状态｜保存
左侧：第一版可放片段列表；第二版加入自动镜头列表
中央：大视频预览（播放、暂停、缩放/适应、当前帧信息）
下方：时间线（播放头、选中区间、缩放）＋逐帧前进/后退、循环、倍速
右侧：第一版为片段起止帧与导入画布；第二版加入镜头切点修正
```

进入页面后先显示视频并允许用户立即播放；是否自动有声播放仍受浏览器策略约束。首期帧索引作为后台任务显示进度。逐帧功能可以等待对应位置的索引/解码准备，页面应明确提示，而不冻结整个播放器。用户在时间线上选择起止帧，预览区间后保存片段引用。第二期在左侧由用户点击「开始分镜」后才启动后台检测；检测前和检测期间均可播放和手动挑片段，随后在左侧查看镜头并校正切点。

## 建议的首版功能边界

1. 原片/兼容预览播放、音量、倍速、全屏或放大预览、可视时间线。
2. 基于**源视频实际帧时间戳**的上一帧/下一帧、帧号与时间码显示，以及跳到指定帧。可变帧率素材按实际帧序列处理，不把平均 FPS 当成每帧固定间隔。
3. 手动选择起止帧、预览和保存时间片段；片段可作为**引用原片起止帧的资产**加入画布流程。片段拆帧读取原片，不从低画质预览缓存取正式帧。
4. 第二版优先讨论自动镜头边界检测、镜头列表、手动加切点、移动切点和合并相邻镜头。自动结果先作为可修正草稿，重新检测不能覆盖人工修改。
5. A/B 帧对照、节奏/色彩统计、笔记、PDF/长图导出和多轨剪辑先列为后续候选；第一版不因为参考软件具备这些功能就全部实现。

## 建议的技术路径

- 浏览器 `<video>` 用于通常速度的播放和声音；视频内容由 MOWO 的 Range 接口提供，必要时使用下载阶段生成的兼容预览。
- 精确逐帧由服务端媒体分析工作进程提供：扫描视频流建立 `frameOrdinal → PTS/时间戳 → 最近关键帧` 索引；按帧请求通过关键帧定位并解码目标帧，缓存附近帧。前端的播放头以源视频时间轴为准，按帧暂停时切换到精确解码画面。需验证帧号、可变帧率、B 帧、旋转元数据和音画切换，不承诺原生 `<video>` 的 seek 精度等于逐帧精度。
- 第二版镜头检测独立于播放器，采用 TransNet V2/ONNX；检测输出源帧切点、进度和可用的置信信息，用户修正作为独立编辑层保存。参考软件已由用户用真实动画样本验证，MOWO 接入后再验收结果、耗时和播放流畅性。
- 片段初期保存为 `sourceAssetId + startFrame/endFrame`（或等价的准确 PTS 边界）及来源关系，不立即复制或转码整个视频。真正导出独立 MP4 时再执行后台渲染任务；画布拆帧仍引用源原片和片段边界。
- 编辑页状态（播放头、选中镜头、面板折叠）与可长期复用的镜头修正/片段资产分离；原片和兼容预览在数据身份上分离。

## 需与用户讨论

这些产品选择已在[视频编辑 PRD](video-editor.md)中确认：首期支持多个片段、选区循环和画面放大；第二期由用户点击左侧「开始分镜」后启动检测，失败不影响手动片段；片段作为原片引用导回现有视频卡片，独立 MP4 导出由画布视频卡片提供。

## 开源方案适配性：2026-11-12 初评

| 方案 | 适配结论 | 原因与需验证事项 |
| --- | --- | --- |
| lapian-player 整体移植 | 不建议 | 它是 Qt/C++ 本地播放器，包含 D3D11 渲染与自有时间线；MOWO 是浏览器里的 Next.js 工作台。可借鉴帧索引、关键帧定位和缓存策略，但整体移植将引入原生桥接与第二套 UI。其源码为 MIT，技术适配而非许可是主要障碍。 |
| CadensView 整体移植 | 不可直接完成 | 仓库的 `THIRD_PARTY_NOTICES.md` 明确它只包含选出的核心源码，未包含完整桌面应用；MOWO 也需要自己的 React 工作区。可进一步评估其独立 Python 媒体、检测和镜头领域模块，但必须核对依赖、性能、许可和数据契约。 |
| [Video.js 10 React 组件](https://videojs.org/docs/guides/installation/react) | 可选的普通播放层，不是专业编辑页方案 | 官方提供面向 React/Next.js 的 `@videojs/react`、可组合控件和样式，可承担播放、声音、倍速、全屏；但不提供截图所示按帧缩放的工作时间轴、可靠源帧定位、镜头检测和片段关系。若其控制栏与专业工作区集成成本高，直接采用原生 `<video>` 更合适。其 [v10 许可](https://github.com/videojs/v10/blob/main/LICENSE)为 Apache-2.0。此前提到的 Vidstack 已被其维护者[标为由 Video.js 10 接替](https://github.com/vidstack/player)。 |
| PyAV + FFmpeg 独立媒体进程 | 值得优先验证逐帧核心 | PyAV 提供容器、包、解码帧及时间戳的精细访问；可与 MOWO 下载阶段的 Python/FFmpeg 交付路径共用运行环境，但应为独立媒体任务，避免耦合下载状态。需验证长视频索引速度、随机定位、可变帧率与缓存。 |
| TransNet V2 / ONNX | 第二版已确认检测路线 | 用户已在 CadensView 安装文件中验证实际分镜效果；MOWO 须接入自身工作进程和镜头数据，并验证模型来源、CPU 性能及交付方式。 |

当前架构为：浏览器负责连续播放和界面，独立媒体进程负责源帧索引、解码及第二版 TransNet V2 检测。参考项目公开的检测核心可作为实现依据；MOWO 自行管理任务、数据和界面，并核对所用源码与模型的来源、许可证和数据边界。

### 与 MOWO 当前架构的连接方式（待验证）

1. 在 Next.js 编辑页的客户端区域用原生 `<video>` 或 Video.js 10 承担连续播放，读取现有素材 Range 接口或兼容预览。普通播放层可替换，不决定专业时间轴的实现；先验证是否有必要引入 Video.js。
2. 可缩放时间线、逐帧按钮、左侧列表和右侧边界面板由 MOWO 的 React 组件实现，共享同一源视频时间轴。缩放只改变时间轴显示密度，不修改素材；保存片段仍走 MOWO 的资产/项目关系。播放器自带的常规进度条不能代替可编辑时间线。
3. 独立媒体工作进程按需为原片建立可持久复用的帧序号/PTS 索引，逐帧查看时返回目标源帧图像。前端暂停普通播放、显示该图像并同步时间码；恢复连续播放时按该源帧时间戳定位。此路径与下载任务状态隔离，可共用已经验证的本地 Python/FFmpeg 供给方式。
4. 第二期让镜头检测任务消费同一源帧时间轴，增量回传候选边界/进度；左侧逐步出现检测结果，用户修正另存。播放与手动挑片段无需等待检测结束。

验证时至少用 H.264 和 HEVC 兼容预览、可变帧率、带 B 帧及长视频样本检查：进入页即可手动播放；精确帧画面与源文件帧号/PTS 一致；逐帧与连续播放切换不明显跳帧；后台索引/检测不阻塞播放；片段边界和导回画布保持原片来源。若 Video.js 10 接入现有 Next.js 版本或自定义时间线成本不合适，普通播放层可退回原生 `<video>`，其余业务接口保持不变。

### 参考软件源码复核与用户截图：2026-11-12

用户提供的 lapian-player 截图展示的是**专业观察工作区**：中央大画面、帧号/时间码、逐帧控制、底部可缩放帧刻度与总览条、侧边标记/截图/信息。此前把 Video.js 10 称为“首选验证对象”容易造成它能提供整页能力的误解，现将它降为可选的连续播放控件。专业时间轴与精确逐帧才是需要优先验证的核心。

已直接读取本地 `lapian-player-main.zip`：`src/core/TimelineModel.cpp` 以 `pixels_per_frame` 和滚动偏移实现帧号/屏幕坐标映射、鼠标位置为锚点的缩放、可见帧范围和播放头跟随；`src/app/TimelineWidget.cpp` 绘制刻度与播放头并处理拖拽、滚轮缩放和边缘自动平移。`src/media/FrameIndex.cpp` 保存帧 PTS 与关键帧，`src/media/MediaSession.cpp` 的定位路径包含顺序解码、邻帧缓存、最近关键帧后解码及 PTS 校验；`src/app/MainWindow.cpp` 先显示首帧，再由独立线程建立索引，索引完成前禁用依赖准确帧号的时间轴和逐帧按钮。其 Qt/C++ 时间轴不能直接装进 React 页面，但数据模型、索引准备状态及缓存策略可作为实现参考。

已读取用户提供的 `CadensView-main.zip`：`t0/media.py` 通过 PyAV 解码建立显示帧的 PTS/时长/关键帧索引，并提供源文件变更检查和准确帧读取；`shotlab/detection/core.py` 要求**完整索引**才启动检测；`shotlab/detection/onnx.py` 按窗口推理并发布已确认的部分切点；`shotlab/analysis_worker.py` 通过 JSON 行输出部分结果，检测时可按播放状态主动让出处理时间；`shotlab/domain.py` 用整数源帧定义相邻镜头边界及半开区间，提供拆分、合并和移动切点；`shotlab/storage.py` 用 SQLite 保存项目和镜头。其仓库 `THIRD_PARTY_NOTICES.md` 明确只公开部分核心代码，不含完整桌面应用，因此播放器和时间轴 UI 仍只能依据截图/README 观察，不能宣称已经审查其具体实现。检测可边运行边发布结果，但按当前源码**不能在完整建帧索引前开始**；“看视频不等分析完成”仍可做到，因为播放无需等待索引与检测。

## 核验限制

CadensView 的完整桌面 UI 未在公开仓库中提供；已核对的源码仅覆盖仓库公开的核心模块。把其中 Python 代码接入 MOWO 仍需另行验证依赖分发、任务进程、源文件索引格式和第三方模型许可。以上技术路径为对 MOWO 架构的设计推断，不是两款参考软件已经证明的 MOWO 实现。

## 2026-11-17 人工校正交互与独立运行环境讨论

用户确认：左侧提供「校正分镜」按钮；开启后可直接编辑时间轴上的镜头分割线，移动或删除切点，左侧镜头列表随有效边界即时变化。当前时间轴的蓝色范围是当前镜头，青色竖线是切点；编辑对象是切点，蓝色范围随切点变化。模式外继续沿用点击、拖动时间轴定位源帧的现有行为；模式内拖动切点按源帧边界吸附，删除切点合并相邻镜头，在当前源帧新增切点拆分镜头。用户明确不需要「保存修改」按钮：松开拖动或点击操作后立即保存，使用 Ctrl+Z 撤回本页操作。检测运行中不编辑尚未稳定的切点。自动结果与人工修正分开保存，重跑不能覆盖人工结果或已保存片段。

在独立运行环境实现前，`data/video-runtime/shot-runtime.json` 曾指向用户安装的 CadensView 目录；MOWO 自己的 `transnet_worker.py` 负责读取源帧索引、调用 ONNX 推理并提交切点，并非启动 CadensView 桌面程序。现在分镜从项目内运行环境定位依赖与模型；只复制源码到没有准备依赖和模型的另一台电脑，分镜仍不能运行。MOWO 独立运行环境要从可分发来源准备、校验和定位 Python、PyAV、ONNX Runtime、DirectML（可用时）及模型，形成 MOWO 自身的依赖清单和启动检查，并在另一台 Windows 电脑验证 CPU 回退、显卡加速和同片结果；不能以用户本机的安装路径作为交付配置。现有 `video:setup` 主要准备下载/媒体运行依赖，不等于已经准备好分镜模型与全部推理依赖。

# 设置与模型接入需求

## 目标

为本地画布提供语言模型和后续生图模型的设置入口，秘密配置只由本机服务端读取。

## 已确认需求

### REQ-SETTINGS-001 设置入口

产品需要提供设置入口，并在设置中预留模型 API 管理区域。设置入口的最终位置和页面结构后续确认。

验收：原型能表达设置入口；模型能力不会散落在多个不一致的页面中。

### REQ-SETTINGS-002 模型 API 管理

配置设计分别管理语言模型和生图模型，覆盖服务商、接口地址、模型、密钥和连接测试。当前 V1 基础对话使用服务端环境配置，界面只展示配置状态。模型切换、密钥保存和连接测试界面待实现。后续阶段见 [AI 长期路线](../../ai/agent-implementation-plan.md)。

验收：语言模型和生图模型配置可以区分；未配置时界面显示明确状态。

### REQ-SETTINGS-003 密钥安全

API 密钥仅由本机服务端读取。正式配置界面只能展示配置状态和遮蔽标识。受保护的本机存储在正式设置上线前评审，可选操作系统凭据库或独立加密存储。加密密钥需要独立保护。

验收：前端、画布文档、Git、日志及示例数据均无可读取的真实密钥。

### REQ-SETTINGS-004 当前画布的会话操作

- 提问靠右、回复靠左，消息之间留出间隔；复制与发送时间等辅助信息仅悬停或键盘焦点进入消息时显示，触控环境保持可用。
- 顶部不再显示“AI 助手”固定标题。左侧 Logo 打开相关设置，标题点击后原位改名；右侧按新建会话、历史会话、放大/还原和折叠排列。
- 历史只展示当前画布的会话，支持名称搜索；悬停行显示重命名按钮。默认会话标题使用第一次提问；手动命名后不被自动标题覆盖。
- 同一页面内扩大对话区，再次点击恢复原宽度；切换会话不修改画布，也不把其他会话的消息作为上下文发送。

验收：旧对话升级后可恢复；历史没有其他画布记录；两处改名入口一致；重复新建空会话不会产生重复草稿；消息悬停与放大/还原在浏览器中验证。

### REQ-SETTINGS-005 提问卡片 UI 优先

先完成助手需求确认卡片的 UI 样式与可检查的本地交互，再于后续讨论适当追问的模型行为。样式预览必须清楚标识，不混入真实会话，不自动发送或调用模型。当前候选见 [提问卡片 V01](../../design/prototypes/clarification-card-v01-preview.md)。

验收：用户能在对话栏打开预览，检查选项、分页与按钮样式；预览操作不产生聊天消息、运行或费用。

### REQ-SETTINGS-006 输入区操作入口

输入区底部区分功能菜单、模式选择、模型偏好和发送/停止；模式表示任务类型，模型偏好表示使用的具体模型。首版功能菜单只提供上传文件，@ 引用与其他功能等有明确用途后加入。当前先实现 UI，未接入能力要有清楚标识。样式与实现边界见[操作栏 V01](../../design/prototypes/chat-composer-v01-preview.md)。

验收：加号菜单没有未经确认的附加功能；文字对话与停止仍可用；预览文件不会被误标为已发送给模型。

### REQ-SETTINGS-007 基础文字对话与恢复

在当前画布的会话内流式回复、复制文本、停止并保留已收到的内容。刷新或断线后先恢复原请求。确认原请求未收到时沿用原请求标识重试；用户主动「重新生成」才发起新请求，并提示可能计费。重新打开同一会话后恢复消息顺序和状态。

验收：发送或查询失败后不会重复生成；停止与完成竞态以服务端记录为准；中断保留部分回复并显示真实状态。接口语义见 [AI 对话运行接口](../../api/ai-runs.md)，验证覆盖见 [V1 进度](../../ai/v1-progress.md)。

## 已确认的后续方向

- 右侧对话面板调用已配置的语言模型或生图模型。
- 生图结果直接成为当前画布上的图片模块。
- 模型接入发生在核心画布与本地保存稳定之后，不属于首个原型。

## 待确认

- 第一批支持哪些国内可访问或可自托管的模型服务。
- API 配置是全局生效，还是允许项目覆盖。
- 本地密钥采用操作系统凭据库、加密文件还是其他安全存储方案。
- 对话请求如何选择模型，以及生图参数放在对话区还是生成模块中。

# 动图拆帧需求

## 目标

把一张或多张动图解析为可查看、可复用、保持原始时间顺序的序列帧集合，并让这些集合能够整体拖入画布或继续交给后续拼接模块处理。

当前实现基线为 [动图拆帧 V03 原型](../../design/prototypes/animated-frame-extraction-v03.md)。功能结构与视觉样式均已确认，第一版已进入实现验证。

## 已确认需求

### REQ-FRAME-001 多动图输入

布局组可通过右侧「组内素材」一次连入拆帧节点。连线或输入素材变化后自动检查并按素材 ID 去重。节点显示可拆帧、静态、不支持、无法读取和已有结果的数量。明细按需展开，可临时取消勾选；默认选中可拆帧的新素材。仅在检查完成并有已选素材时可以开始，检查失败可重试。

“动图拆帧”模块提供一个允许多条连接的图片输入端口。用户可以把画布上的多张动图同时连接到模块，再通过明确的“开始拆帧”操作批量处理；每个输入独立显示进度和结果，单个输入失败不应中止其他输入。

验收：多个 APNG 或 GIF 图片模块可以同时连接；开始后分别产生结果或分类错误；新增输入可以单独处理而不重复拆解已经完成且参数未变化的来源。

### REQ-FRAME-002 独立序列帧组结果模块

误删画布上的结果组后，可在原拆帧节点点击「恢复结果组」，从原任务重新显示已保存的序列和未提交的项目草稿，并重新连接结果组。恢复不重复解码；旧任务的历史到期时间不影响恢复。

首次拆帧成功只自动生成并连接「动画帧批次」。批次采用真实画布父子组，每张来源动图是独立、可移动的折叠子组，展开后在画布上按序显示帧。批次框下方的附属按钮首次点击创建「动画帧编辑」并连线，再次点击定位到已有编辑卡。新增来源追加到同一批次。

结果模块内的每张来源动图是一个折叠的序列帧集合：以前景第一帧缩略图作为封面，后方显示多层轻微错位的图片重影，不使用 Windows 文件夹图标。结果模块提供组数与总帧数摘要；来源名称、尺寸、总时长等详细信息在打开组后查看，避免把画布节点做成信息面板。

验收：用户无需阅读说明即可区分普通图片、处理模块和序列帧集合；处理模块内不出现结果卡；批量结果组与处理模块之间存在明确连接；多个折叠组在顶部有序展示，共用展开区且一次只展开一个，切换时不会反复改变外层高度。

### REQ-FRAME-003 逐帧查看与组切换

画布内共用序列编辑区提供“详细编辑”按钮，点击后打开逐帧查看窗口。窗口采用左侧大预览、右侧帧缩略图结构，打开后默认播放动画，不显示“动画播放/当前帧”切换。左侧预览下方提供上一帧、播放/暂停和下一帧；暂停即停留在当前帧，点击缩略图或逐帧按钮会定位并暂停。窗口显示帧序号、时间位置和停留时间，顶部提供“上一组”和“下一组”，无需关闭窗口即可在本次拆解的多个动图结果之间切换。

验收：画布快速编辑区可以打开详细窗口；窗口中不存在播放模式切换条；打开后自动播放，暂停后画面保持不变；点击任意帧可在左侧静态查看并暂停；再次播放后从当前帧继续；切换上一组或下一组后显示对应来源与帧列表，组边界和当前组序号清楚可见。

### REQ-FRAME-004 拖入画布生成序列帧组

结果模块内的堆叠序列帧组可以整体拖到画布。释放后创建一个画布组，组内每一帧是独立图片模块，并按集合顺序从左到右、从上到下采用自适应网格排列和编号。重复拖入只创建新的画布组与模块实例，不重复保存物理帧文件。

验收：整组可移动和删除；组内单帧可独立选择与连接；删除画布组不删除序列帧资产；同一结果再次拖入不会生成第二套物理文件。

### REQ-FRAME-005 序列帧资产集合

每张来源动图对应一个 `Frame Sequence（序列帧集合）`。集合成员保持原始帧位置、时间位置和停留时间；允许不同位置引用内容完全相同的图片资产。导出的帧是应用动图混合与处置规则后的完整画面，不是只包含变化区域的残缺帧。

验收：相同画面可以在一个序列中出现多次且时间信息各自正确；帧序列重新打开项目后仍可恢复；透明背景和画布尺寸保持正确。

### REQ-FRAME-006 派生资产与来源关系

序列帧图片属于从原动图生成的派生资产。系统需要保存本次处理的输入资产、输出集合、输出图片、处理类型、处理参数和处理版本之间的关系。后续再次编辑产生的新资产继续形成新的派生记录，不能覆盖原始资产或只靠文件名表达来源。

验收：可以从任意序列帧追溯到来源动图和拆帧处理；重新处理不会破坏旧结果；物理文件去重不应丢失业务上的来源关系。

### REQ-FRAME-008 第一版格式范围

第一版动图拆帧支持 APNG 和 GIF。动态 WebP 延后到获得真实样本并完成解码兼容性验证后加入；静态图片接入时应明确提示其不包含多个动画帧。

验收：APNG 和 GIF 能生成保持透明度、尺寸、顺序与帧时长的完整 PNG 帧；动态 WebP 不会被误报为已经支持；静态输入不会产生伪造序列。

### REQ-FRAME-007 与图片拼接模块衔接

下一步图片拼接模块将接收有顺序的图片集合，例如把 12 帧按 4×3 或其他布局拼成一张图片。动图拆帧输出必须保留稳定顺序和原始像素，不能为了预览缩小正式帧文件；拼接产生的图片同样是派生资产，并保留从序列帧集合到拼接图片的来源关系。

验收：序列帧集合可以不经过重新上传直接作为拼接模块输入；拼接使用正式帧资产而不是缩略图缓存；拼接结果可追溯到输入集合和间接来源动图。

### REQ-FRAME-009 弹窗视觉复用边界

逐帧查看窗口可以与图片下载窗口共用对话框外壳、棋盘格预览台、缩略图网格、缩略图卡片和基础翻页控件。下载链接、任务轮询、临时文件选择、导入与归档逻辑不得进入逐帧查看；帧索引、帧时长、播放时序、组切换和“将本组放入画布”逻辑不得进入图片下载。

验收：两个窗口视觉一致但业务状态互不影响；修改 LINE 下载任务流程不会改变逐帧查看行为；修改帧播放逻辑不会影响下载弹窗。

### REQ-FRAME-010 批量结果组与折叠编辑

动画帧编辑可同时连接动画帧批次、单个拆帧子组和手动有序图片组，同一序列只显示一次。组必须有明确顺序且所有直接成员都是可预览的图片，否则显示提示。手动组的排序、移除和时长修改同步回画布并随画布保存；移除帧会将对应节点移出组，画布撤销可恢复。拆帧子组采用同样的有序成员表示，排序、移除和时长修改写回原任务草稿。详细逐帧查看可切换所有已接入的序列。旧画布已有的批量结果卡继续可打开，保留原序列草稿。

已保存序列在项目资产中以一张堆叠卡展示，首帧作为封面。展开后可拖出单帧，拖动序列卡可整组放入画布。资产范围可显示序列中已有帧在画布上的数量，并定位到对应画布节点。未保存的草稿留在动画帧批次。

批次内序列小组由拆帧任务生成，不能拖离批次，也不接收任意外部素材。小组的「复制到画布」先保存当前序列，再以正式帧资产创建一个可独立移动的有序组；原批次仍保留结果与来源关联。

批次持久尺寸只包住折叠封面的原位置；展开帧组时使用临时画布布局，不把展开区尺寸固化为批次高度。再次折叠或重新打开旧画布时，批次框应收紧。复制出的独立组放在批次当前可见范围下方，间距由可见布局计算，不使用可能遗留的旧高度。

普通组可直接「设为有序组」，多选静态图片可直接「组成有序组」。两个入口先检查所有成员，只有已导入且可读取的静态图片才通过；动图、视频、文字、空节点和子组会显示具体提示。PNG/APNG、GIF、WebP 依实际文件帧数判断，不按文件名判断。检查失败时保留原组和素材。

转为有序组后立即排齐，初始顺序按当前位置从上到下、同一行从左到右确定。组内图片使用统一展示尺寸，按帧顺序从左到右、从上到下排列并显示编号。拉宽或缩窄组框自动换行，图片原文件尺寸和播放顺序保持有效；「整理」按现有帧顺序排齐并收紧外框。旧有序组打开后先检查静态素材，再应用同一布局。

组内单张图片拖动时显示插入提示，松手后更新帧序并让其他图片归位；拖出原有序组边界时仍在原组中完成排序。多张同时拖动在松手时归位，批量换序通过动画帧编辑完成。复制图片按钮把副本插入当前帧下一位，复用资产并继承停留时间。删除或从编辑器移除帧后重新排齐。手动编辑的顺序和时长随画布保存，并可通过画布撤销恢复。

组工具栏提供「播放预览」；更多菜单可「转为普通组」。图片工具栏可设置停留时间并应用到全组，范围 1 至 3600000 毫秒，手工图片默认 100 毫秒，来自拆帧的图片继承原时长。手动有序组可另存为正式序列资产，引用已有图片，相同内容重复保存复用集合。

拖入图片、替换图片、导入编号图片或从资产栏放入序列时同样检查实际内容。新导入的动图可进入项目资产库，但不会替换有序组的静态帧或加入该组。无法读取的素材不用于有序组播放、帧编辑和正式序列保存。

### REQ-FRAME-011 草稿删帧与最终保存

拆出的全部帧先作为任务草稿进入临时区，不立即成为正式项目资产。用户可以在展开区多选帧并执行“从序列移除”，也可以撤销；从组内拖出单帧默认只复制到画布，不修改草稿。点击“保存序列（N帧）”后，只有当前保留成员进入正式序列帧集合和派生关系，被排除候选帧不进入长期资产库。

验收：12 帧草稿可以删到 4 帧并只保存包含 4 个成员的正式集合；原始动图不被修改；保存前意外关闭可以在临时保留期内恢复；保存成功后未保留候选文件被清理；相同内容帧仍能在不同序列位置重复引用。

动画帧编辑区在保存期间由按钮显示「保存中」，成功后仅将按钮改为不可重复提交的「已保存」，不在按钮下方重复显示成功提示；失败时在同一区域提示原因并允许重试。关闭后重新打开，已保存来源仍显示「已保存」。未保存的拆帧序列和删帧、排序、时长编辑持续作为项目草稿保留；新拆帧任务不得清理它们。保存成功的正式序列不随草稿清理消失。

## 待确认

- 自适应网格的默认列数，以及是否第一版就允许用户手动切换横向、纵向和固定行列。
- 用户主动“导出到普通文件夹”时的人类可读目录与文件命名规则。
- 删除来源动图时，对仍被序列帧集合或拼接结果引用的派生链采用禁止删除、仅解除项目关联还是保留来源墓碑记录。
- 拼接模块的行列、间距、背景、尺寸和超大图片限制将在下一轮单独确认。
### 动画帧拼接

通过动画帧批次下方入口或左侧「动图处理」创建拼接节点。输入可以是整批或一个序列子组，按当前保留的帧顺序生成每组一张 PNG。预览可选列数、间距、外边距和背景。结果进入可下载的图片组，派生记录保留裁回所需坐标与帧时长。

## 参考项目的实际结构

Concat 的截图 `assets/editor-dark.png` 显示：上半部为素材库、预览、属性面板；下半部为独立时间轴。时间轴从上到下有工具栏、时间尺、播放头、轨道与滚动区。视频片段以连续画面缩略图识别内容，音频有波形；选中片段有明确轮廓。时间轴右上提供缩放，尺上的秒数随缩放变化，而片段的实际时长不变。

源码的职责分布：`src/crates/concat/ui/timeline/lanes.slint` 处理片段绘制及指针命中；`ui/workspace/timeline-pane.slint` 组合尺、轨道和滚动条；`src/panes/timeline.rs` 管理缩放、水平滚动、吸附及跟随；`concat-project/src/commands/clips.rs` 定义拆分、移动、修剪、删除等命令；`concat-project/src/editor.rs` 把一次操作记录为可撤销步骤；`concat-project/src/placement.rs` 使拖动预览与正式落点采用同一放置规则。预览和导出另有独立模块。

| 用户动作 | Concat 的实现要点 | MOWO 取舍 |
| --- | --- | --- |
| 辨认片段 | 视频轨道在片段内排列取自素材的画面；尺、播放头与片段共用时间比例 | 必须有缩略画面、成片时间尺与播放头；只做一条无间隙视频轨 |
| 缩放和平移 | `seconds_per_pixel` 表示时间比例；缩放以指针位置为锚点；水平滚动独立于播放位置 | 下方剪辑时间轴独立缩放、适应全片、横向滚动；不改变上方源帧时间轴 |
| 选择与定位 | 指针按下先明确选择；片段、边缘、时间尺分别命中；超过约 4px 才算拖动 | 点击片段只选中；点击片段上下空白区域定位；拖动不足阈值不改工程 |
| 移动 | 以窗口坐标计算位移，防止元素移动后局部坐标变化；悬停预览与落点规则一致 | 用固定内容坐标定位，拖动时显示片段、目标空位和插入位置，松手一次提交 |
| 修剪 | 悬停边缘显示水平调整光标，边缘与片段主体不共用命中区 | 两端独立把手，预览修剪结果，松手后提交，短片段仍可选中 |
| 撤销 | 编辑命令成功才入历史；连续手势合为一个步骤 | 沿用现有共用撤销/重做，拖动松手只提交一次 |
| 播放与导出 | 工程片段顺序驱动预览和导出 | 沿用 MOWO 的成片→源帧映射和 FFmpeg 导出，并用实际素材核对二者一致 |

## 当前 MOWO 的可用性问题

原 `cutting-strip.tsx` 把整段视频压成容器宽度的 50px 高色块，片段只有文件名和帧数。长视频里短片段小到难以辨认，两端各 10px 的把手继续挤占片段主体。下方没有时间尺、缩放和平移，拖动预览只有数字文字；对用户来说看不到要剪掉的画面，也无法确信放手后的落点。此前隔离测试证明数据与导出可运行，没有证明这些编辑动作可实际使用。

## MOWO 改造边界和验收

1. 保留上方原片分镜与源帧时间轴；下方是按成片顺序排列的单条视频轨，默认显示约 20 多秒范围，支持适应全片、缩放与横向滚动。
2. 片段显示取自源帧的缩略画面及源帧范围。缩略图按可见片段宽度稀疏采样、延迟加载，不一次解码长视频的每一帧。
3. 片段主体点击只选中；上方尺或下方空白区点击、拖动才定位成片时间。拆分用选中片段和播放头。边缘修剪与主体重排使用不同命中区和光标。
4. 拖动超过阈值后显示目标空位与跟随预览；修剪时显示新的片段宽度和边界；松手才写入工程与撤销历史。所有操作继续以源帧半开区间保存，不改原片或自动分镜。
5. 用实际可辨认、带音频的素材验收：放大到能选中短片段，点击选中不跳帧；在不同位置拆分、修剪、删除、交换顺序，连续预览与下载 MP4 的画面、声音顺序一致；刷新后仍是同一工程，撤销/重做有效，保存回画布不重复。

不引入 Concat 的 Rust/Slint 界面、多轨、转场、特效、字幕、音频独立编辑及工程格式。画面裁切、移动、缩放属于后续单独设计。

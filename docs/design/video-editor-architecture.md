# 视频编辑页技术设计

> 2026-11-16 更新第二期自动分镜路线。对应[视频编辑 PRD](../requirements/features/video-editor.md)。本页保留总体设计，实际完成状态见[实施进度](video-editor-progress.md)。参考项目的实现不直接等同于 MOWO 实现。

## 源码依据与取舍

- 本地 `lapian-player-main.zip`：`TimelineModel` 以每帧像素数、滚动偏移和视口宽度做帧坐标映射；`TimelineWidget` 处理缩放、拖拽、刻度、播放头及边缘自动平移；`FrameIndex` 记录 PTS 与关键帧；`MediaSession` 优先顺序解码、邻帧缓存，随机定位回到关键帧后解码。先显示首帧，索引在后台建立。Qt/C++ UI 与 D3D11 渲染不移植到 Next.js。
- 本地 `CadensView-main.zip`：`t0/media.py` 用 PyAV 建源显示帧索引并读取精确帧；`shotlab/domain.py` 用整数帧与半开区间定义镜头拆分、合并、切点移动；`shotlab/detection/` 用完整索引运行 ONNX 检测并逐步发布已确认边界；`shotlab/analysis_worker.py` 用 JSON 行报告结果并在播放时让出资源。仓库声明仅公开部分核心，不含完整播放器与时间轴 UI。可评估 Python 核心复用，不预设直接复制代码。

## MOWO 模块边界

```text
Next.js 客户端编辑页
  ├─ 连续播放层：原生 video（Video.js 仅作可选控件）
  ├─ 专业时间轴：React 状态 + Canvas 刻度/标记绘制
  ├─ 片段/镜头面板：项目级选择与编辑状态
  └─ 帧画面层：暂停时按需显示媒体进程解出的源帧
        ↓ localhost Route Handler / 服务层
SQLite：正式片段、草稿、后续镜头修正；源帧索引为可重建 SQLite 缓存
        ↓ 独立本地媒体工作进程
原片 + 帧索引缓存 + 按需帧图缓存 + 第二期 TransNet V2 镜头检测
```

播放器只是连续播放层，不能拥有时间轴、片段或镜头数据。页面以 `assetId` 和所属 `projectId` 打开；Route Handler 校验项目资产关系。已有 Range 接口和兼容预览用于连续播放；准确帧始终来自原片。镜头检测复用现有本机进程管理与源资产定位能力，选择经验证的 Python、PyAV 和 ONNX Runtime 工作环境；媒体分析任务与下载任务的状态和执行槽分开设计，防止分析阻塞下载或反过来阻塞播放。

片段有独立稳定 ID、所属项目、源视频资产 ID、起止边界和名称，不生成另一个原片文件。现实现采用 `video_clips` 保存半开帧区间、PTS 和来源；同一 ID 建立一个视频素材资产卡，物理路径引用原片，不参与内容哈希去重。画布节点保存片段 ID、来源与边界，服务端入库时核对完整帧索引；源原片被片段外键引用。已保存片段边界在首期不可变，从旧片段编辑并保存创建新 ID，既有引用不重定向。`video_clip_drafts` 是用户主动保存的项目草稿，不作为资产。

## 时间轴与逐帧协议

1. 唯一的选择坐标是源显示帧序号；索引记录 `ordinal、PTS、duration、keyframe anchor`，保留源视频流时间基、旋转和来源文件指纹。不要用 `currentTime + 1/fps` 定义下一帧。播放中的 UI 可按时间估计位置，但在执行逐帧、设切点或保存片段前必须解析到实际源帧。
2. 时间轴视图保存 `pixelsPerFrame`、`scrollFrame/scrollPx`、视口宽度和跟随播放头开关。缩放围绕鼠标所在帧，限制在适应全片与单帧清楚可见之间；仅绘制可见刻度和缩略图，避免长视频为每帧创建 DOM。总览条与放大视图指向同一范围。
3. 打开页立即建立连续播放会话，并独立排队索引。索引完成前可以播放、暂停和粗略跳转；逐帧、按帧切点与片段保存明确标示待就绪。索引完成后用源帧映射修正 UI，不能让已播放画面突然跳动。
4. 精确定位请求携带 `assetId、ordinal、requestGeneration`。工作进程从最近关键帧解码到目标帧，并缓存邻帧；新请求代次使旧响应失效，快速拖动只保留最后目标。返回目标帧图像和实测 PTS；若不匹配索引则报错并触发索引重建或降级提示，不显示错误帧。
5. 逐帧时暂停连续播放层，精确帧图覆盖画面并同步帧号/时间码；恢复连续播放时将浏览器视频定位到该帧 PTS，待画面就绪再撤去覆盖层。浏览器 seek 与源解码可能短暂不一致，需在验证中测量切换延迟和可见跳帧。
6. 片段边界存为 `[startFrame,endFrame)`，并关联原片与项目。导回画布时创建片段身份和画布引用，原片不复制；播放片段按索引换算边界时间，正式拆帧仍按源帧读取。若浏览器循环/停止在边界处有误差，界面不能把它解释成精确导出结果。
7. 首期选区循环和画布片段卡片都以选区的源帧边界换算播放时间；现有视频节点只有完整视频 URL 和原生控件，需增加片段身份、限定起止与片段相对进度。浏览器 `timeupdate` 触发频率随负载变化，不能把它作为帧准确停止的保证；播放边界精度须做样本验证，正式帧选择和拆帧仍以索引为准。
8. 画面放大平移只改变显示变换，不写入原片或片段定义。精确帧覆盖图和连续播放视频必须使用同一显示变换，避免切换时画面位置跳变。

## 后台任务衔接

- 索引任务以源资产内容指纹和索引算法版本作为缓存键。状态至少区分等待、运行、完成、失败、源文件已变更；生成临时文件后校验并原子提交。重启后核对源文件与索引再恢复，不复用半成品。
- 首期播放请求不等待索引任务。按需精确帧读取应有独立的交互优先级和小容量缓存；后台扫描对 CPU/磁盘让路。窗口关闭后索引可按本机任务策略继续或安全中断并重启恢复，不能只靠页面内存保活。
- 第二期进入编辑页时只查询检测结果与任务，不自动排队。用户点击左侧「开始分镜」时才以当前项目和原片原子创建任务；重复点击或重复请求复用同一有效任务。检测依赖完整索引，索引尚未完成时显示等待状态，播放仍可立即进行；按已完成的分析窗口增量发布**已确认**切点，未确认尾部保持待处理。播放期间降低分析资源占用，用户切换项目或删除原片时按任务生命周期规则处理与原片的关联。
- 自动镜头结果与人工修正分层保存。检测重跑生成新的候选集，不覆盖已保存的人工边界或已导入画布的片段。失败只影响检测能力，不影响原片播放、帧索引或手动片段。
- 草稿属于项目与源视频的编辑状态，不是正式片段资产；只在用户主动选择「保存为草稿」后持久化。正式片段编号应由项目/源视频维度的持久递增序号生成，删除后不回收号码，避免重名或草稿占号。页面内导航可用自定义三选项弹窗；浏览器关闭/刷新只能提供系统通用警告。

## 第二期自动分镜实施顺序

1. **检测核心验证（首版必需）**：固定 TransNet V2 模型、哈希与推理版本，按源显示帧和参考实现的图像预处理、分析窗口及边界规则运行。先在海贼王真实样本上产出整数帧切点，由用户核对关键片段；再检查长片处理时间和播放是否仍顺畅。检测器只输出候选，不改原片或现有片段。
2. **后台任务与数据（首版必需）**：为原片建立可查询的分析任务与结果，记录源文件指纹和检测版本；按窗口报告真实进度，完成后提交连续镜头范围。重复进入页面复用有效结果，失败显示原因并允许重试。自动切点和人工修正分开保存；源视频变化时旧结果失效，重跑不覆盖修正或已保存片段。
3. **观察页闭环（首版必需）**：左侧提供「开始分镜」，点击后才排队检测，播放器与手动片段编辑始终可用；逐步显示已确认镜头及缩略图，点选镜头同步播放器和时间轴。支持在源帧上移动切点、手动拆分及合并；选定镜头沿现有“仅保存到素材库／保存并放入画布”流程生成片段。用户使用同一海贼王样本核对完整检测与校正结果。
4. **依赖交付（交付前收尾）**：为 MOWO 独立取得并校验模型、运行依赖及其许可材料，验证 Windows 本机启动、取消、重试和重启后任务状态。参考软件的安装文件仅用于本地效果核对，MOWO 交付物由自身依赖清单构建。GPU 加速在 CPU 路径稳定后按实际性能需要接入（按需增强）。

## 首轮技术验证门槛

实施顺序先做**内部验证闭环**：安全入库或打开既有资产 → 编辑页播放 → 粗选时间区间 → 用临时数据验证片段素材与画布卡片的连接。粗选结果只能是草稿或测试夹具，不能写成用户可复用的正式片段资产，也不能对外宣称完成片段回画布。随后实现完整源显示帧索引、按帧切点、精确逐帧和正式保存，再验收首期闭环；镜头检测仍属第二期。草稿保留用户原始时间位置，索引就绪后显示吸附到源帧的候选边界并请用户确认，不能静默改写任何已保存片段。

用真实动画样本和合成的恒定/可变帧率样本验证：长视频打开到可播放的等待时间；索引运行时播放不卡顿；帧号与源 PTS 一致；连续前后步进、随机拖动与反复放大时间轴；H.264、HEVC 兼容预览、B 帧、旋转、音画起点偏移；连续播放与精确帧图切换；关闭页/重启后任务与缓存恢复；片段边界在画布播放及后续拆帧的一致性。若帧索引需要全片解码、耗时过长，应先保证播放与局部观察，显示分析进度，不把后台完成伪装为即时能力。

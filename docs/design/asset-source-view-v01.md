# 资产栏按来源整理 V01

**状态：当前最新设计，首版代码已接入，待浏览器交互验收。** 本文记录已讨论确认的交互，以及落地时需要处理的数据边界；默认资产列表保持平铺。

## 用户流程

1. 在「当前项目资产」旁点击设置，选择「平铺」或「按来源」；默认平铺，保持现有范围筛选、格式筛选和搜索。
2. 选择「按来源」后，列表按「下载」「导入」折叠展示。以后有 AI 生成能力时可增加来源区，不提前显示空分类。
3. 一次下载入库的多个素材显示为同一批次文件夹，默认用首个素材作封面，以入库日期时间命名，可重命名。展开后是各原始素材。单独导入的原始素材直接排列，不强行创建批次文件夹。
4. 用户可以在来源区新建、重命名手动文件夹，将不同批次进入项目的**原始素材**移入同一文件夹，例如同一角色的多次导入或 12 张序列帧。手动文件夹不接收衍生品，整理操作不改变素材来源或文件内容。手动文件夹与下载批次文件夹是不同概念；将下载批次中的素材移入手动文件夹后，该批次列表不再显示第二张卡片或“已移走”占位，批次历史改在该素材的信息面板中查看。
5. 文件夹、下载批次、原始素材与产物均用尺寸稳定的方块网格展示；侧栏变宽时增加列数，卡片本身不拉长。点击文件夹或批次逐层进入，以面包屑返回。原始素材保持放入／定位画布的卡片操作；存在已保存产物时，独立的「查看产物」入口进入该原图页面，页面先显示原图，再显示相关产物。拆帧序列占一个集合方块，进入后再显示成员帧。移动原始素材到其他手动文件夹时，相关产物跟随显示。尚未保存的画布处理预览不算资产产物。
6. 两个或更多源素材共同生成一个结果时，每个源素材的「相关产物」均显示指向**同一结果**的关联卡。结果只保存一份，详情显示全部直接输入；从任何入口打开都是同一结果。后续再处理该结果时，通过派生链继续追溯到原始素材。
7. 搜索、格式筛选和「在画布上／不在画布上」仍作用于资产本身。文件夹显示匹配数量，展开仅显示匹配项；搜索产物名时，应显示其源素材路径，避免结果被折叠层级藏住。「在画布上」按资产是否被画布引用计算，不因其文件夹或关联卡在列表中出现而改变。
8. 同一内容再次导入当前项目时，仍只显示一个原始素材和一个当前整理位置。新入库事件追加到来源记录；界面提示素材已存在并提供定位，用户可自行移动，不自动从旧文件夹挪走。

## 素材信息面板

画布上图片节点已有「信息」快捷按钮。点击后，将现有的名称、像素尺寸等简短浮窗扩展为可读的素材信息面板；资产栏卡片也应能打开同一份信息。信息从**当前项目**视角查询，避免把另一项目的文件夹误显示在此处。

建议按下列顺序排版，缺失的字段不显示空行：

1. **素材**：缩略图、显示名称、格式、像素／时长、入库时间。资产 ID 放在可展开的技术信息中，不占据主视线。
2. **目前位置**：例如「下载 › 小熊」；未整理时显示「下载 › 11 月 12 日下载」或「导入」。提供「在资产栏定位」。这是当前展示位置，可随手动整理改变。
3. **最初来源**：例如「LINE 下载」「批次：11 月 12 日下载」「原始素材：小熊挥手.png」「来源链接」。即使素材已从批次列表移出，这些记录仍保留。派生素材还应逐项列出直接输入的素材名称，例如「来源素材：小熊挥手.png、背景.png」；多次入库事件按时间折叠为「来源记录（2）」，不把第二次导入误说成另一个素材。
4. **相关产物**：逐项显示实际名称和类型，例如「小熊挥手·序列帧（12 帧）」或「小熊合成.png」，并可进入该产物；多源产物可查看全部直接输入。原始素材没有产物时不显示该区。产物较多时先显示少量条目与「查看全部」，不只显示数量。

「最初来源」和「相关产物」中的每个素材或集合条目都显示当前画布状态。若有画布实例，给出醒目的「定位画布」按钮，点击后平移／缩放到对应实例并选中；同一资产有多个实例时沿用现有多实例定位规则。若不在画布，显示中性的「未在画布」状态，名称仍可复制、在资产搜索栏检索或点击「在资产栏查找」。发光强调只用于可执行的画布定位按钮，不用于整行或无实例条目。序列帧集合的状态依实际帧成员或结果组的画布引用判断，并在详情中说明定位目标。

资产搜索必须索引当前项目内的素材显示名、原始文件名以及序列集合名。搜索结果展示匹配项本身和其来源路径；即使匹配项位于折叠的产物区，也应提供可打开该层级的结果，不要求用户预先知道文件夹位置。

「目前位置」回答现在在哪里，「最初来源」回答如何进入项目，两者不得互相覆盖。来源链接应以可识别的平台名称和“打开来源”按钮展示，不以一整行长 URL 撑宽面板。移动文件夹只修改目前位置；来源历史、文件内容和派生关系均不变。

## 结构与边界

| 概念 | 作用 | 是否允许手动整理 |
| --- | --- | --- |
| 来源分类 | 下载、导入，以及未来实际接入的生成来源 | 否 |
| 下载批次 | 一次确认入库的多个原始素材；保存下载时的顺序和来源 | 可重命名展示名，不改历史来源 |
| 手动文件夹 | 用户跨批次整理原始素材的展示容器 | 可新建、改名、移动原始素材 |
| 原始素材 | 初次进入项目的资产；可作为处理链根节点 | 可移动到手动文件夹 |
| 相关产物 | 从原始素材沿派生关系可追溯的资产或集合 | 不直接移入手动文件夹 |
| 多源产物关联卡 | 同一产物在每个相关源素材下的入口 | 不是资产副本 |

画布布局组与资产栏手动文件夹互不等同。序列帧集合保留成员顺序；手动文件夹中的素材默认无序，不能因为放在同一文件夹就自动成为序列帧。

文件夹是数据库中的组织关系，不建立同名磁盘目录；现有哈希文件路径保持不变。重命名文件夹不修改资产文件名或来源。由于相同内容可复用同一个全局 `asset.id`，文件夹归属必须按项目记录，不能写在全局 `assets` 行上。若同一项目再次导入相同内容，需要保留每次入库事件／批次成员关系，不能仅靠复用后的资产 ID 推断“第一次导入”或“属于哪个批次”。

派生关系是有方向的图，而文件夹只是浏览视图。多源产物不指定任意一个“主来源”；两个入口引用同一产物 ID。删除某个入口、移出手动文件夹、删除真实产物是不同操作，界面必须明确区分；首版可只提供查看和移动原始素材，产物删除沿用现有资产删除规则，不为关联卡提供容易误解的删除按钮。跨项目复用资产时，当前项目的文件夹和来源视图不应自动继承另一项目的整理结果。

- 使用已保存的项目验证真实 LINE 下载批次、单独导入、重复入库、拆帧、裁切和多源拼接。重点核对搜索、画布范围筛选、刷新后的文件夹归属和跨项目复用。

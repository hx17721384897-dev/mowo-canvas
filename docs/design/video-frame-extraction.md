# 视频拆帧设计与实施计划

状态：当前有效设计，2026-11-18按最终讨论更新。产品验收见[需求](../requirements/features/video-frame-extraction.md)。

## 用户流程与节点线框

视频工具栏创建并连接节点。每个输入选择「动画／拍摄视频」，连接时仅读取资产元数据检查时长和大小，不解码计数。超限显示原因和编辑页裁剪入口；片段真实准备大小在执行时校验。通过后直接点击「生成图片组」。动画识别连续相似画面、推断目标帧率并按比例还原独立帧位；拍摄视频不合并相似帧。依据不足时停在卡片请求确认目标帧率，不擅自把每个画面仅留一张。

```text
视频拆帧
素材类型：[动画] / [拍摄视频]
大小、时长通过 → [生成图片组]
  动画：分析保持段 → 推断或确认目标帧率 → 按比例还原
  拍摄视频：保留源帧，不合并相似画面
处理结果≤150张 → 旁边直接生成批次组和有序子组
处理结果>150张 → 当前共242张，等待选择：
  [仅输出前150帧] [抽帧] [进入编辑页裁剪]
  抽帧：每N帧保留前K帧 → 即时显示121张 → [确认抽帧并输出]
```

输出直接走现有批次组与有序子组，再连接现有动画帧编辑或拼接，无视频专属帧编辑页面。单来源保留现有动图批次外壳规则。待确认来源调整参数后继续原批次，明确重新生成才新建批次。

生成请求带deferOutput=true，允许执行者把超限/节奏不足结果保存成analyzed待确认来源，此时不写PNG或创建该来源草稿。其余来源可直接完成。确认通过PATCH action=confirm重新排队原任务中指定的待确认来源，保留同一resultTaskId及已完成子组，重复确认返回原状态。只有主动选择「仅输出前150帧」才带truncate=true；末张时长不延长到原片结尾。抽帧确认不截断，仍超限时继续等待。旧调用不传deferOutput保持原有错误行为。

## 实现组织

共用 FrameExtractionTask / FrameSequenceDraft / FrameDraft、草稿保存、正式集合、结果组、编辑窗口及拼接。入口检查与解码按动图/视频分支，动图不执行相似分析。避免复制结果 UI。

现有 findProjectImages、inspectImage、decodeFrames、输入端口类型与固定动图文案需要扩展。现有任务接口同步解码不适合分析视频；视频使用异步任务入口，共用任务结果读取与后处理。执行者复用项目媒体运行时，不新建常驻服务。任务持久状态包含阶段、进度、取消标志、错误和处理参数；重启后未完成任务明确失败并允许重试，不伪装继续执行。

### 范围与资源

所有范围使用源显示帧半开区间及实际 PTS；片段直接解码原片范围，正式帧不取兼容预览。先做廉价元数据检查，允许范围才分析。

完整原片按真实文件字节数检查。引用片段的字节数先显示估算；执行前将所选片段视频轨按 CRF18/yuv444p 封装到受限临时文件（复用精确源帧边界语义，不调用会传送下载响应的导出接口），监控字节数超过 200 MiB 即停止，再以实际文件检查。该准备有编码开销，显示 preparing 阶段并允许取消；不能按源文件体积拒绝片段。准备文件只用于大小判断，正式分析与 PNG 仍读原片。

逐帧流水处理、顺序执行来源、监控临时空间。阶段 2 确定初始保护值：最多 7200 源帧、单帧 4096×2160 像素量、宽×高×源帧数最多 40 亿、PNG 总量 512 MiB、可用磁盘保留 512 MiB、工作进程 600 秒。它们是额外资源底线，不把 150 个输出等同于只解码 150 帧；超限返回明确原因。大型素材组合的设备验收仍在阶段 5。

### 节奏及时间

先识别完整画面连续保持段，再结合实际停留时间及全片重复规律提出还原帧率。已验证本机 FFmpeg mpdecimate 对 4/6/2 基准保留三个代表画面；正式实现使用既有 PyAV/NumPy，避免依赖滤镜丢帧日志去推测完整源映射。以保持段首图为参照，完整 RGB 分辨率计算差异；平均差≤1.2、最大 8×8 块差≤3、像素最大通道差>12 的比例≤0.002 才归入同段，避免连续小变化无限累积。

自动建议检查至少六个保持段、源时间间隔稳定、内部至少两种保持长度，在常用 23.976/24/25/29.97/30 帧率中筛选；候选只提供编辑建议，不证明原作者帧率。变量帧率、单一保持长度、短样本或多个候选均要求手动指定。细微局部动作、实际 CRF23 压缩和切镜合成用例已通过，但不保证恢复有运镜、粒子或复杂转制的手绘节奏。

用户指定还原帧率后按累计时间边界分配整数帧位，避免逐段四舍五入累积漂移；每个画面段至少保留一个帧位，无法满足时提示目标帧率过低。还原得到重复的独立帧位，再执行 N/K 抽帧。保留帧覆盖后续被跳过的时间，使整体播放时长保持。

补充 sourceKind、源范围、源帧起止、源 PTS/时间基、还原/抽帧参数及算法版本；编辑 timelineStartMs 与原始时间分开，禁止把输出位置冒充源帧号。重复图片可共用物理内容，各帧位必须有独立 ID。旧动图记录缺省为动图，不改旧数据语义。必要字段迁移在接入前完成。

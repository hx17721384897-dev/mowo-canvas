# B 站视频下载与入库 V01 设计书

> 当前有效方案：2026-11-12 用户已确认精简首版范围，A—D 已完成实现与交付验证，待用户体验验收。本文描述“下载 → 预览 → 确认入库”的当前设计；证据见[实施进度](video-download-progress.md)，按需增强见[后续迭代清单](video-download-backlog.md)，业务规则见[视频下载 PRD](../requirements/features/video-download.md)。

## 1. 首版目标

在当前画布左侧“功能 → 下载 → 下载视频”打开独立下载弹窗，完成 B 站登录、链接解析、单个分 P 与画质选择、下载、预览和确认导入当前项目素材库。首版同时只执行一个视频任务，记录写入 SQLite；关闭弹窗继续执行，重启后找回记录并明确标为已中断，允许用户重试。

范围：普通投稿 BV 链接、BV 号、受控解析的 b23.tv 短链、单个分 P。只显示本次账号和视频实际可用的格式，不承诺固定 4K/60fps。多 P 批量、其他内容类型与平台、手动暂停、并行下载不进入首版。

画布节点、本地视频导入和视频编辑各有自己的需求文档。下载完成不自动铺到画布，也不自动启动分镜、拆帧或编辑。当前本地视频导入与基础画布播放已有实现，下载资产应沿用统一资产身份；后续放置行为由对应画布需求控制。

## 2. 用户流程与界面

1. 弹窗展示链接输入、登录状态和当前项目历史任务，不混入其他项目任务。与 LINE 图片下载分开管理状态，可复用现有弹窗外壳。
2. 解析链接得到标题、来源、封面、时长、分 P 和实际格式。短链只能经受信任的跳转到普通 B 站视频，移除跟踪参数。无法解析时显示明确原因。
3. 提供程序内扫码、刷新二维码、扫码待确认、过期、成功、退出登录。登录成功前校验会话，登录状态跨重启保存；失效时允许重新扫码。
4. 用户选择一个分 P 与清晰度；默认兼容性优先，选择可用的最高 H.264/AAC MP4 组合，也可选择其他实际可用编码。大小未知时显示未知，不伪造百分比或体积。
5. 开始后显示下载、合并、校验、待导入、已导入等阶段。合并和校验没有可靠百分比时使用阶段提示。弹窗可关闭，任务继续；本机服务退出会停止其工作进程。
6. 校验成功的原片可以确认导入。原片可播放则直接预览；不兼容时自动生成独立兼容预览。预览生成中或失败不阻止原片入库，明确显示状态并提供重试入口。
7. 用户确认后写入当前项目素材库，显示视频标识、封面或占位、时长及预览入口。重复入库复用相同内容，不覆盖原片、不重复复制物理文件。

HDR 首版不承诺兼容预览；未支持的色调映射应明确提示，仍保留可入库原片。

## 3. 首版技术结构

```text
VideoDownloadModal
  → Next.js Route Handler（参数、项目归属、接口状态）
  → VideoDownloadService（任务记录、单任务调度、导入编排）
      ├─ SQLite 视频任务表
      ├─ B 站扫码 + Windows 当前用户加密凭据
      ├─ 单一执行者 + 已有文件锁和 Job Object 守护链
      │   → Python yt-dlp 引擎 → FFmpeg/ffprobe
      └─ 统一 Asset / 项目引用 / 本地原片与预览缓存
```

主应用保持 TypeScript/Next.js；视频处理使用独立 Python 进程，通过 UTF-8 JSON/NDJSON 回报状态。工作进程不直接写数据库。Cookie 只在服务端或受控进程中使用，浏览器不接收 Cookie、签名媒体 URL 或本地绝对路径。

继续使用已有 guardian、managed-worker、winjob、locks。已完成的 Job 残留收束保留使用，不继续扩展为多协调器系统。首版不增加领导权选举、SQL 租约、租约代次或完整接管工作流。心跳只用于父进程存活检测。

普通 npm dev/start 由统一入口管理 Next 与一个单任务执行者，复用已验证的 run-app 守护链。第二个执行者拿不到互斥锁时停止领取，不等待“接管领导权”；关闭任一服务后整组收束。

运行环境使用固定版本和绝对路径，依赖来源、哈希和许可有记录。D 已将 Python 从实验版本更新到固定哈希的 3.14.10 并回归；不依赖用户系统 Python、PATH 或 line 项目。当前基线见[运行材料](video-runtime-notices.md)，Windows 安装包另行评估。

## 4. 简单任务模型与重启规则

原片状态采用 queued、downloading、merging、verifying、ready、importing、completed、failed、cancelled、interrupted；解析与选择留在弹窗/解析会话，不为每个临时界面动作创建正式下载任务。预览状态单独记录 pending、generating、ready、failed、not-needed。

首版增加一个视频任务表：任务 ID、项目 ID、规范化来源/BV/CID/分 P、选择的格式、状态、进度、错误摘要、相对文件路径、已验证媒体信息、重试次数、当前执行标识、导入后的 assetId 和时间。来源字段保存在任务记录中；不同来源任务可引用相同资产。completed 记录不自动清理，资产保留自己的基础来源信息。

每次手动重试更新当前执行标识，旧执行的迟到结果不能改变新一次运行的状态。这是单任务本地校验，不建立独立 attempt 表或分布式租约协议。任务写入及导入更新使用必要的 SQLite 事务和唯一约束。

启动时先确认旧受控进程停止，再把未正常结束的执行状态及 queued 记录标为 interrupted，等待用户重试。已校验且文件仍存在的 ready 任务继续待导入；文件缺失应明确提示重新下载。排队记录保留，不在重启后未经用户操作自动批量执行。

已有来源身份匹配及 Range 检查可在用户重试时复用。满足条件才尝试续下；不能确认时保留现场并提示重新下载。服务器忽略 Range 时显示重新下载，不能声称恢复了进度。不承诺自动续下所有任务。

## 5. 文件与入库底线

- 下载先进入数据目录中的任务专属临时区；校验容器、视频轨、尺寸、时长和实际要求的音轨。无声视频不强制增加音轨。
- 通过校验的原片才可以入库。大小和时长不采用本地上传接口当前的 5 分钟/500 MiB 作为下载上限；长片可以先留在素材库，放到画布或进入编辑时再按对应产品规则分流。
- 使用文件流计算内容哈希与发布原片，不能整部视频读入 Buffer。正式目录按统一资产规则管理，文件不得覆盖已保存内容。
- 导入保留临时原片直到数据库提交成功。数据库事务内完成资产创建/复用、项目引用、任务 assetId 与 completed 更新。重复点击返回既有结果；导入失败保留来源供重试。
- 文件准备后、数据库提交前中断，可能留下未引用的正式文件；首版通过哈希核查后重试复用，不自动删除无法确认归属的文件。暂不实现 VideoImportIntent、阶段日志和自动崩溃修复。
- 导入中断后先按任务 assetId 与事务结果核对，已提交则返回结果，未提交则允许用户重试。不能把仅存在目标文件当作入库已完成。
- 原片与兼容预览分开，预览是可重建缓存。复用已有转码与媒体检查；预览活动期间保留原片，清理前停止并等待读取进程结束。
- 内容读取采用文件流及 GET/HEAD、Range 206/416；复用或扩展现有视频读取能力。封面与视频 URL 分开，不把视频作为图片加载。

## 6. 删除、空间和备份的简单规则

项目有运行中、排队、待导入或 interrupted 未处理的视频任务时，拒绝删除，提示用户先导入或明确放弃；生成中的预览同样属于活动处理。取消需等待进程树停止后才允许清理。删除单项与批量项目统一在服务层检查，批量中任一项目不满足时不执行该批删除。

任务创建、导入与项目删除的检查需要相互一致的数据库事务边界，避免检查结束后新增任务的竞态。涉及 LINE 运行中或待导入任务时，也应遵守同样的“先处理任务再删除”条件；不重构 LINE 下载器。

允许用户清理已失败或取消任务的临时文件；已完成任务清理临时残留不影响正式资产。待导入的唯一原片不自动清除。首版先用固定规则和明确的手动清理，暂不加入空间设置页、延期和复杂淘汰策略。

下载前检查可用磁盘空间，合并/预览及运行中仍需监测；空间不足时停止或拒绝新处理，显示原因并保留安全文件。未知体积不等于无限空间，不以整片内存缓存代替磁盘处理。

备份沿用项目既有方案，界面明确正式资产与临时下载的边界。首版备份相关数据时要求先停止视频处理，并提醒先导入待保留素材；恢复后缺少临时文件的任务标记需重新下载。暂不实现在线备份屏障和下载现场自动恢复，也不重做整个备份系统。

## 7. 已有成果如何处理

| 已有成果 | 当前事实 | 首版处理 |
|---|---|---|
| 扫码、DPAPI 凭据、跨进程恢复 | B 已接正式弹窗，实测边界见进度 | 保留使用 |
| yt-dlp 解析、格式选择、下载与合并 | B 已接正式接口与短链校验，实际样本通过 | 保留使用 |
| ffprobe、兼容预览、Range 续下判定 | 已实现并验证 | 复用；续下仅作重试优化 |
| Job Object、文件锁、取消与进程树回收 | 已实现并验证 | 保留使用，不再扩大多协调器测试 |
| 残留 Job 主动收束 | 已完成代码及测试 | 随守护链保留，不制造高级接管产品流程 |
| Next 启动与单执行者 | 普通 npm 入口已接统一守护链并回归 | 保留使用 |
| 本地视频导入、资产与画布播放 | 当前项目已有另一条实现路径 | 复用边界，核对接口；不直接复用其时长/大小限制 |
| SQL 租约、完整 attempt/导入日志、删除隔离、备份屏障 | 未实现 | 移入后续清单，首版不补齐 |

完成了代码和实验不等于完成了产品集成。保留可复用成果，不因延期某个完整系统而删除已经有效的基础机制。

## 8. 剩余实施顺序与验收

| 检查点 | 工作 | 验收结果 |
|---|---|---|
| A. 最小数据与接口 | 视频任务表、当前执行标识、状态/错误校验、项目范围、基础来源与导入引用 | LINE 旧数据不受影响；重启可查任务；同一时刻一个执行者 |
| B. 可操作的下载弹窗 | 接正式扫码、短链、分 P/画质选择、下载进度、取消、重试和项目历史 | 用户可从界面完成一次真实下载；关闭弹窗继续；重启明确显示中断 |
| C. 确认入库与预览 | 复用媒体和资产能力，流式校验、幂等入库、封面、视频预览及 Range | 原片保留；失败不假入库；重复点击不复制；无声/不兼容编码状态正确 |
| D. 单执行者交付与收尾 | 统一启动、项目删除阻断、空间不足、清理、备份范围提示、运行版本和许可材料 | 取消无后台写入；活动任务阻止删除；重启可重试；基础成功/失败路径及 LINE 回归通过 |

不再把高级恢复日志、多协调器租约、删除隔离和在线备份故障矩阵列为上述检查点的完成条件。后续能力的触发条件和状态统一见后续清单；不承诺全部必做，也不安排当前工期。

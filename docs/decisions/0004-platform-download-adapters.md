# ADR 0004：平台下载采用适配器与本地持久任务

状态：Accepted  
日期：2026-11-02

## 背景

用户已有一个成功下载 LINE APNG 和 B 站视频的 Python/Flask 工具。MOWO 当前采用 Next.js、TypeScript、SQLite 与统一资产目录。直接嵌入旧 Flask 服务会引入第二套页面、任务状态、下载目录、依赖和进程生命周期。

## 决定

- LINE 下载使用 TypeScript 重新实现，复用旧工具已经验证的商品识别、元数据地址、CDN 地址顺序、Emoji ZIP 与 APNG 处理知识，不复制 Flask、Streamlit 或页面代码。
- 平台差异隐藏在下载适配器后；弹窗、任务、临时文件和资产导入不依赖 LINE 专有结构。
- 下载任务保存在 SQLite，文件先进入任务临时目录，用户确认后才进入资产模块。
- B 站视频下载不进入本次范围。未来继续使用隔离的 Python `yt-dlp + FFmpeg` 工作进程，不重写下载引擎，也不把 Python 加入 MOWO 主运行时。
- 当前接口仅在 localhost 内部使用，不形成公开平台 API。

## 原因

该结构保留旧工具已经验证的行为，同时让 MOWO 只有一套界面、任务状态和资产身份。未来增加平台时只新增适配器，不改写弹窗或资产模块。

## 结果

- LINE 代码需要重新实现并重新验证成功与失败路径。
- 下载任务会增加 SQLite 迁移和临时文件清理责任。
- 代理通过服务端配置注入，不硬编码本机端口。
- B 站接入前需要单独设计工作进程、凭据安全存储和版本锁定。

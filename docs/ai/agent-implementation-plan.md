# MOWO Agent 分阶段实施计划

更新日期为 2026-11-05。用户已确认本计划书，作为当前唯一 AI 实施计划。尚未完成的能力与技术验证在文中明确标注。

## 产品目标

近期优先完成基础对话和图像生成。@ 引用、联网搜索及画布操作类 Skill 分后续版本推进。

用户在当前画布右侧与助手对话，通过 @ 指定素材，按需搜索资料、调用 Skill 和画布工具，并通过图像模型生成可继续编辑的图片。项目继续采用本地单用户架构。模型请求由本机 Next.js 后端发往所配置的供应商，会话、资产与任务记录存入本地数据目录。

首期语言模型计划使用 DeepSeek。具体模型、上下文限制、视觉输入与工具调用能力以接入时验证的官方资料及实测为准。

## 技术方案

现有侧栏负责折叠、宽度与布局。优先评估 assistant-ui 的消息、输入和工具结果展示组件，AI SDK 负责模型调用和流式传输，项目后端负责权限、上下文组装、任务执行与持久化。组件与当前 Next.js、React 版本的兼容验证属于第一阶段前置工作。

调用路径为「右侧助手 → 本机 Agent 接口 → 上下文与工具执行模块 → 模型或外部工具」。画布与资产操作复用现有业务接口。

| 职责 | 设计 |
| --- | --- |
| 侧栏 | 消息、引用标签、运行状态、停止与重试、工具结果 |
| 模型配置 | 服务商、模型、默认选项、连接测试和密钥引用 |
| Agent 运行 | 组装上下文、限制步骤、执行工具、记录状态与用量 |
| 供应商适配 | 语言模型、搜索、图像模型分别接入 |
| 业务工具 | 查询资产、创建节点、拆帧及后续能力 |
| 本地保存 | SQLite 保存会话、任务与关系，文件进入既有资产目录 |

## 阶段 0：准备与兼容验证

### 画布变更的执行与交接约定

V2 生图放置与 V5 画布工具共用以下规则。服务端产出资产或工具结果，并保存待应用操作。当前编辑器在浏览器内基于最新内存状态应用增量，再通过已有撤销与串行保存链路确认完成。

- 操作记录包含 operationId、projectId、runId、操作类型、输入与输出引用、预先分配的节点 ID 及载荷版本。状态至少包括待应用、已应用待保存、已保存、失败。
- 编辑器验证项目及引用后应用操作，使用操作 ID 与稳定节点 ID 去重。一次操作形成一个可撤销步骤。用户撤销后记录撤销意图，恢复运行时不会重新放置同一结果。
- 浏览器应用成功后报告待保存；后端确认画布快照保存成功后才确认操作已保存。应用成功但确认丢失时，恢复流程按稳定 ID 检查已保存画布，避免重复节点。
- 画布未打开、编辑器已退出或应用失败时，结果保留为待放置。再次进入时提示恢复，按最新画布状态应用。
- 生图等新增节点操作可以基于最新状态合并。删除、替换或修改现有节点时携带前置条件，节点已改变或消失时进入冲突处理，提示重新确认。
- 本期执行前提为每个画布一个活动编辑器。多标签或多窗口写同一画布的版本检查需在实施前验证并约束，不能仅依赖前端去重。

阶段 0 接口草案必须给出操作投递、去重、应用回执和保存确认契约。验收覆盖生成期间用户继续编辑、离开画布、重复投递、保存失败、确认丢失和撤销后恢复。未来若采用服务端直接修改画布，先建设文档版本检查与冲突处理。

整理 DeepSeek 官方资料，验证模型调用、流式输出、中断及工具调用。用隔离测试画布验证 assistant-ui 和 AI SDK 与现有依赖的兼容性，再锁定版本。

梳理画布现有保存、撤销、拆帧任务、资产去重和派生关系的接口。Agent 操作必须经过这些接口，并接入相同的保存链路。

开发前确定密钥保存方式。初期技术验证可使用服务端环境变量，设置页面上线前落实操作系统凭据库或独立加密存储；加密密钥需要独立保护。配置接口只返回是否已配置和遮蔽标识。

交付为依赖验证记录、模型能力清单和首版接口草案。通过真实 API 的成功、超时、无效密钥与中断路径后进入 V1。

## V1：可持久保存的对话

### 用户体验

设置中提供「语言模型」配置，包含供应商、模型、密钥输入、保存与连接测试。右侧顶部显示当前模型与连接状态。消息区支持流式回复、停止、复制与失败重试。每个画布先提供一个稳定会话，切换画布后恢复对应记录。

### 后端与保存

浏览器提交当前用户消息，由后端读取会话历史并发起模型请求。消息与运行分别保存，避免把半段回复记成正常完成。运行至少区分待执行、生成中、成功、失败、中断。

设定上下文长度预算，历史超出预算时明确采用截取或摘要策略，并保留本地原始记录。记录供应商用量与错误分类；可见错误使用可操作的中文提示，诊断日志使用运行 ID 关联。

### 验收

- 刷新、返回首页再进入后，消息顺序和内容一致。
- 双击发送、请求重试与网络中断不会产生重复用户消息或伪成功回复。
- 停止生成后保留已收到内容并标记中断。
- 密钥不进入前端公开配置、画布文档、Git 或日志。

### V1 重试契约补充

- 客户端提交时生成 clientRequestId，同一次请求重发沿用该 ID。数据库对会话 ID 与 clientRequestId 建立唯一约束，先记录运行再调用供应商。
- 相同 ID 与相同输入返回已有 runId 和状态，已完成时返回已存结果。相同 ID 但输入不同返回 409。输入摘要包含消息、引用快照、模型及生成参数。
- 流断开后按 runId 查询，尚未拿到 runId 时按会话 ID 与 clientRequestId 查询。服务端保存累计消息与事件序号，前端恢复已有运行。
- 用户主动「重新生成」使用新请求 ID，并关联原运行。进程退出留下的生成中运行在重启后标记中断或待核实，避免无限等待。应用侧幂等不能保证供应商对重复付费请求只计费一次。
- 验收覆盖并发重复提交、返回 runId 前后断流、刷新恢复与服务重启。正式接口文档须落实这些规则。

### V1 停止与断线契约补充

本计划采用断线后继续生成方案，独立运行执行机制提前到 V1 建设。创建请求先持久记录运行并交给本地后台执行器，浏览器通过独立的事件订阅与状态查询获取输出。模型调用由执行器持有，浏览器订阅断开不会取消上游调用。后续 V2 复用该机制扩展图像任务。

V1 执行器负责运行领取、持续保存输出、检查停止意图与重启核对。执行租约过期后，旧执行实例的写入必须被拒绝。重启时将无法继续的语言模型请求标记中断或待核实，保留已保存内容，由用户决定是否重新生成。浏览器关闭后继续运行的前提是本机执行器仍在运行。

阶段 0 必须验证创建运行、独立订阅、关闭页面后持久完成、主动停止与执行器退出的完整路径。V1 验收通过前落实上述机制。

- 浏览器流断开或页面关闭只结束订阅。服务端仍可继续生成并持久保存回复，客户端重新连接后查询运行状态。执行器意外退出时标记为中断或待核实。
- 用户点击停止时，通过带 runId 的独立停止请求通知后端。该请求幂等，后端记录停止意图并取消上游请求，保留已持久化的部分回复。界面先显示停止中，收到后端确认后显示已停止。停止供应商计费的能力以其接口为准。
- 停止与完成使用同一运行状态的原子条件更新。若完成已提交，停止返回已完成；若停止先被接受，后续迟到的完成事件不能覆盖用户停止状态。传输关闭事件本身不代表成功。
- 停止请求未确认时，客户端查询状态或重发停止请求。服务重启时处理已记录的停止意图。验收覆盖停止请求丢失、重复停止、完成竞态、断线后完成与进程退出。

## V2：图像模型与生成入画布

此阶段优先跑通输入文字提示词、生成图片并加入画布。参考图与 @ 引用能力根据后续 V3 及所选供应商能力扩展。

设置中增加独立的「图像模型」配置。首版接入一个供应商，具体模型及参数待确认。侧栏提供明确生成入口，显示文字提示词和供应商支持的尺寸等参数，提交前呈现付费操作边界。参考资产显示与输入安排在 V3 扩展。

采用持久任务处理生成、轮询、下载与入库。任务保存供应商任务 ID、输入、参数、状态和结果。刷新页面后恢复查询。网络重试优先查询已有任务，供应商支持幂等时使用同一请求标识。

生成文件下载并验证后，通过现有资产模块去重入库。V2 保存提示词、模型版本、参数及任务到输出资产的关系，V3 再扩展参考资产与派生输入关系。图片完成后在发起画布中创建节点，记录已放置的节点 ID，恢复任务时避免重复放置。画布已经关闭时保留结果，并在再次进入时展示待放置提示。

### 执行器与重启核对

V2 复用 V1 的本地 Node.js 后台执行器，增加图像任务的领取、供应商轮询、结果下载与资产入库。任务以 SQLite 持久队列管理，通过带过期时间的执行租约领取。应用启动时启动或连接执行器；重启后核对过期租约和供应商状态。执行器运行期间，即使页面关闭，也可继续轮询、下载和入库；本机进程全部退出期间暂停，重新启动后恢复。

远程提交前持久记录请求标识、输入摘要和提交中状态。获得供应商任务 ID 后立即保存。如果供应商已接单而本地未取得 ID，按供应商幂等键或请求查询能力核对。供应商不提供可靠核对能力时标记为提交状态未知，提示用户核实后决定是否重新付费提交。领取任务、轮询、下载和入库可分别恢复，未知提交不能自动当作失败重发。

V2 验收覆盖执行器退出与重启、租约回收、重复领取、远程提交响应丢失和下载入库中断。阶段 0 须确认首选供应商对上述恢复流程的支持范围。

### 入画布的发布门槛

单活动编辑器约束须在 V2 自动入画布启用前实际实现并验证。采用服务端校验的编辑权限与保存条件，覆盖双标签、双浏览器窗口、断线与权限接管，旧编辑器必须被拒绝保存。只做前端提示或阶段 0 方案核对不满足该门槛。最终实现若使用版本号与冲突处理替代独占约束，需达到同等防覆盖效果。

验收覆盖单张与多张结果、部分下载失败、刷新恢复、重复回调和重复放置。正式资产使用原始生成文件，预览图独立管理。

## V3：@ 引用画布资产

### 用户体验

输入 @ 后出现当前画布素材选择面板，支持名称搜索和缩略图。选中项成为可移除的引用标签。发送前能查看引用列表，发送后消息仍显示对应标签，并可定位画布节点。

引用按资产、集合或节点稳定 ID 保存。首版候选范围、集合整体引用和多选数量在原型中确认。

### 上下文规则

服务端重新核实资产属于当前项目，按需读取名称、类型、尺寸、文字与序列顺序。用户引用图片时，明确区分元数据与真实图像输入。真实图像输入依赖模型视觉能力；视频内容理解需要另行规划。

发起运行时生成输入快照，记录实际发送的资产版本、引用与参数。引用对象随后被移动或移出画布时，历史消息仍可辨认。缺失素材需要明确提示。

发送前提供可展开的「本次发送内容」，逐项显示文字与元数据、实际图片及处理后尺寸和体积。只有具备视觉能力的模型才接收图片内容。网页正文在搜索后获得，在工具结果中展示实际使用的页面与摘录，并遵循本次运行的搜索授权。

后端校验图片数量、单张与累计体积及像素上限，具体数值在阶段 0 按供应商能力确定，取应用与供应商上限中更严格者。缩放和转换生成临时副本，保留原资产；预览使用准备发送的副本。超限时列出原因，由用户减少引用或确认处理方案。展示与最终请求使用同一份经过校验的输入快照。

### 验收

- @ 能查到指定范围内的真实素材，并准确定位。
- 同一资产的多个节点实例可以区分节点位置与资产身份。
- 输入超出数量或体积限制时给出提示。
- 实际发往供应商的内容与界面呈现的引用范围一致。

## V4：联网搜索

在输入区增加搜索开关。首版用显式开关决定是否允许本次运行搜索。搜索由后端工具调用，返回标题、URL、摘要与获取时间，回复展示可点击来源。

供应商需结合大陆可访问性、费用、接口稳定性和中文结果选择。网页正文读取作为独立能力验证。获取到的网页内容作为外部资料输入，工具执行范围由应用控制。

搜索调用设定次数、超时和结果长度预算。搜索失败时显示失败状态，引用链接必须能追溯到真实工具结果。

验收涵盖搜索成功、无结果、超时、限额以及来源对应关系。

## V5：Skill 与画布工具

### Skill 结构

每个 Skill 包含稳定 ID、名称、用途、版本、操作说明和允许调用的工具。用户可显式选择，自动推荐与匹配在后续验证后增加。一次运行记录所使用的 Skill 版本。

Skill 说明指导任务流程，执行能力由注册工具提供。具体操作类 Skill 留到后续版本讨论，再确定第一个场景。

### 执行与画布同步

工具声明参数、输入限制、返回结构、失败分类与是否修改画布。侧栏显示准备、执行、成功或失败及关联结果。对覆盖、删除和付费生成等操作的确认边界，在相应工具上线前确定。

每次工具执行保存稳定操作 ID。重试时复用已完成结果，避免重复任务或节点。画布修改进入既有状态与撤销保存链路；耗时处理交给任务接口，Agent 等待或查询状态。用户停止运行后禁止继续调度新步骤，已发出的远程任务按供应商能力处理。

设定最大步骤数、运行时长和工具调用次数。首版仅开放明确登记的工具。

### 验收

- 一个真实 Skill 能从引用资产完成到画布结果，过程可见。
- 工具失败、中断和重试后，任务记录与画布状态一致。
- 用户编辑画布期间执行工具，不覆盖无关改动。
- 能通过运行记录追溯 Skill、输入与工具结果。

### 后续操作类 Skill 的完成条件

后续实现时分别记录任务完成、草稿可审核、正式集合保存、节点放置与画布保存确认。自动保存权限和人工检查方式随具体场景确认。

## 数据与接口规划

以下为概念模型，落地前编写 Drizzle 迁移和正式 API 契约。

| 记录 | 保存重点 |
| --- | --- |
| ProviderConfig | 类型、供应商、地址、模型、非秘密参数和密钥引用 |
| Conversation / Message | 画布、角色、消息内容、引用与时间 |
| AgentRun | 状态、请求标识、模型、Skill 版本、输入快照、用量与错误 |
| ToolExecution | 操作 ID、工具、参数、状态、结果引用 |
| GenerationTask | 供应商任务 ID、状态、输出资产及画布放置记录 |

接口按配置、会话、运行与图像任务组织，候选路径为 /api/ai/settings、/api/projects/{id}/conversations、/api/ai/runs 和 /api/ai/image-tasks。正式输入、错误码、幂等及取消语义在 [API 文档入口](../api/README.md) 单独维护。

未来源码可集中在 src/features/ai 下，按 settings、chat、context、skills、tools、providers 和 server 分工。阶段内只建立实际使用的目录。

## 迭代与验收方式

每阶段先确认最小场景和原型，再完成可运行实现。先用假响应验证界面状态，再用真实供应商验证核心路径。使用隔离测试项目验证修改与删除；记录测试所覆盖的实际范围。

每次交付同步功能需求、接口契约、文件地图、项目状态和当期日志，完成 Git 存档。稳定验收后再推进下一阶段。工期在阶段 0 完成供应商与依赖验证后估算。

# 账户系统规划

## 当前状态

账户系统不在本地单用户版本范围内。程序启动后直接进入项目列表。

## 引入时机

只有准备让其他用户通过局域网或公网访问时，才进入账户系统迭代。进入前需要确认上线方式、用户规模、登录方式和数据归属。

## 未来能力顺序

1. 用户与会话。
2. 邮箱和密码登录，或由管理员创建账户。
3. 项目所有权与服务端权限校验。
4. 密码重置、邮箱验证或国内短信验证码。
5. 团队邀请、成员角色和项目共享。
6. 根据风险决定是否增加双因素认证。

## 技术边界

- 优先选择可自托管、可连接自有 PostgreSQL 的认证方案。
- 登录页面与认证逻辑分开选择。
- 任何受保护操作都必须在服务端验证会话和权限。
- 不仅依赖客户端隐藏按钮或检查 Cookie 是否存在。
- 密码不得明文保存。
- 社交登录、海外邮件与第三方身份平台不是默认依赖。

## 候选方案

进入该阶段时重新评估 Better Auth、Auth.js 或适合当时需求的自托管方案。当前不锁定具体库，以避免过早绑定和版本陈旧。
